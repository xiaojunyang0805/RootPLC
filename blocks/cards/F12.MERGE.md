# F12.MERGE · `RB_Merge`

**Family:** F12 material handling · **Level:** L2 device module · **Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

Merges two conveyor lanes into one: when the line downstream is clear, one
waiting lane is released until its part has passed the merge eye. With
parts waiting on both lanes they take turns, or lane A has priority.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `WaitingA` / `WaitingB` | in | BOOL | FALSE | a part waits at the end of the lane |
| `Clear` | in | BOOL | FALSE | the line downstream can take a part |
| `MergeEye` | in | BOOL | FALSE | eye after the merge |
| `PriorityA` | in | BOOL | FALSE | FALSE: alternate |
| `Timeout` | in | TIME | T#10s | a released part must pass within this |
| `Reset` | in | BOOL | FALSE | rising edge clears a fault |
| `ReleaseA` / `ReleaseB` | out | BOOL | | run the lane's end section |
| `FromA` / `FromB` | out | UDINT | | parts merged per lane |
| `Error` / `ErrorID` | out | BOOL / UDINT | | fault ([blocks.fault]) |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F12.merge.release]** With nothing released and `Clear`, a waiting
   lane is released; only one lane at a time.
2. **[F12.merge.turns]** With both waiting, the lane not served last goes
   first (A at the start); with `PriorityA`, A always goes first.
3. **[F12.merge.passed]** The falling edge of `MergeEye` ends the release
   and counts the part to its lane; an eye pulse with nothing released is
   not counted.
4. **[F12.merge.timeout]** A release lasting `Timeout` without a part
   passing is fault 1: releases off, none until `Reset` (safe state). Each
   release has its own `Timeout`.

## Faults

| ErrorID | Meaning | Cleared by |
|---|---|---|
| 1 | no part passed the merge eye within `Timeout` | `Reset` |

## Not covered

building.
