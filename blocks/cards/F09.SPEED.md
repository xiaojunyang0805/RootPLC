# F09.SPEED · `RB_ZeroSpeed`

**Family:** F09 supervision and diagnostics · **Level:** L1 elementary
function · **Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

A zero-speed (shaft rotation) monitor: a proximity switch on a shaft or
tail pulley must keep pulsing while the drive runs. No pulse means a
broken coupling, a slipping belt or a blocked conveyor.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `Running` | in | BOOL | FALSE | the drive runs |
| `Pulse` | in | BOOL | FALSE | proximity switch |
| `StartDelay` | in | TIME | T#5s | no check while starting |
| `Timeout` | in | TIME | T#2s | longest gap between pulses |
| `Reset` | in | BOOL | FALSE | rising edge clears a fault |
| `Monitoring` | out | BOOL | | the check is active |
| `Error` / `ErrorID` | out | BOOL / UDINT | | fault ([blocks.fault]) |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F09.speed.start]** Monitoring begins `StartDelay` after `Running`
   becomes TRUE and ends when it goes FALSE.
2. **[F09.speed.gap]** While monitoring, each rising edge of `Pulse`
   restarts the gap timer; a gap of `Timeout` is fault 1.
3. **[F09.speed.fault]** The fault latches until a rising edge of `Reset`;
   the application stops the drive on it (safe state).

## Faults

| ErrorID | Meaning | Cleared by |
|---|---|---|
| 1 | no pulse within `Timeout` while running | `Reset` |

## Combines with

`RB_Motor` (`Running`, and `Error` into its `Interlock`), `RB_Trips`,
`RB_ConveyorZone`, `RB_PulseRate` for the actual speed.

## Not covered

Underspeed against a set speed (use `RB_PulseRate` with
`RB_AnalogLimits`), direction detection.
