# F04.MOTOR.REV · `RB_MotorReversing`

**Family:** F04 device modules · **Level:** L2 device module ·
**Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

Runs a motor forward or in reverse through two contactors that are never
on together, with a dead time between directions, feedback per direction,
a thermal overload input, a mode, an interlock and a permissive.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `Mode` | in | `RB_MODE` | `Off` | `Off`, `Manual` or `Auto` ([blocks.mode]) |
| `AutoFwd` / `AutoRev` | in | BOOL | FALSE | automatic commands (level) |
| `ManFwd` / `ManRev` | in | BOOL | FALSE | manual commands (level) |
| `Interlock` | in | BOOL | FALSE | TRUE stops now, in every mode |
| `Permissive` | in | BOOL | TRUE | FALSE: do not start a direction |
| `FbFwd` / `FbRev` | in | BOOL | FALSE | contactor auxiliary contacts |
| `Overload` | in | BOOL | FALSE | TRUE: thermal overload tripped |
| `Feedback` | in | BOOL | TRUE | FALSE when no feedback is wired |
| `FeedbackTime` | in | TIME | T#2s | supervision time |
| `ReverseDelay` | in | TIME | T#1s | both contactors off at least this long before a direction starts |
| `Reset` | in | BOOL | FALSE | rising edge clears a fault |
| `RunFwd` / `RunRev` | out | BOOL | | contactor outputs, never both TRUE |
| `RunningFwd` / `RunningRev` | out | BOOL | | direction from the feedback |
| `Error` / `ErrorID` | out | BOOL / UDINT | | fault ([blocks.fault]) |
| `Status` | out | `RB_DEVICE_STATUS` | | for the HMI ([blocks.status]) |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F04.rev.exclusive]** `RunFwd` and `RunRev` are never TRUE together.
2. **[F04.rev.both]** Both directions commanded at once: the motor stops
   (no fault).
3. **[F04.rev.dead-time]** A direction starts only after both contactors
   have been off for `ReverseDelay`, counted from the moment the last one
   dropped (also from the block's first call). Changing direction directly
   drops the running contactor at once and starts the other after the dead
   time.
4. **[F04.rev.mode]**, **[F04.rev.interlock]**, **[F04.rev.permissive]** as
   in `RB_Motor`: mode selects the commands, the interlock stops at once in
   every mode, the permissive prevents a start but not running on.
5. **[F04.rev.overload]** `Overload` TRUE is fault 3 at once.
6. **[F04.rev.no-feedback]** A commanded direction without its feedback for
   `FeedbackTime`: fault 1.
7. **[F04.rev.unexpected]** Feedback of a direction that is not commanded
   for `FeedbackTime`: fault 2.
8. **[F04.rev.both-feedback]** Both feedback contacts on for
   `FeedbackTime`: fault 4; `RunningFwd` and `RunningRev` are FALSE while
   both are on.
9. **[F04.rev.fault]** A fault latches and drops both contactors (safe
   state: de-energised); a rising edge of `Reset` clears it.
10. **[F04.rev.no-supervision]** With `Feedback` FALSE, the running outputs
    follow the commands; switching supervision on starts its timers fresh.

## Faults

| ErrorID | Meaning | Cleared by |
|---|---|---|
| 1 | no feedback for the commanded direction | `Reset` |
| 2 | feedback without a command | `Reset` |
| 3 | thermal overload | `Reset` after the overload resets |
| 4 | both feedback contacts on | `Reset` |

## Tests

`conformance/cases/blocks/ok_rb_motor_reversing.st` (7 TEST blocks).
Library mutation score against all block tests: 99% (457 of 459 library
mutants, 5 Nov 2026). The two survivors change `AND` to `OR` in the dead-time timer input;
they are equivalent because the contactors are never on together.

## Combines with

F12 conveyors and lifts, F05 step chains (homing, positioning to limit
switches), F08 alarms on `Error`, F10 mode managers.

## Not covered

Limit switches at the end of travel (the application maps them to
`Interlock` per direction or uses a step chain), variable-speed reversing
(planned drive block), star-delta, safety functions.
