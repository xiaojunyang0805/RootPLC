# F09.SIGNAL · `RB_SignalMonitor`

**Family:** F09 supervision and diagnostics · **Level:** L1 elementary
function · **Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

Diagnoses an analog signal that is in range but wrong: frozen (a blocked
impulse line, a transmitter hanging on its last value) or changing faster
than the process can (a loose wire, a burst pipe).

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `Value` | in | REAL | 0 | the signal |
| `Enable` | in | BOOL | TRUE | FALSE: no diagnosis (e.g. plant stopped) |
| `StuckBand` | in | REAL | 0.1 | a move larger than this is a movement |
| `StuckTime` | in | TIME | T#60s | no movement this long: stuck |
| `MaxRate` | in | REAL | 0 | units/s; 0: no rate check |
| `Stuck` | out | BOOL | | the signal is frozen |
| `RateHigh` | out | BOOL | | it changes faster than `MaxRate` |
| `Rate` | out | REAL | | units/s since the previous call |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F09.signal.stuck]** The signal moved when it differs from the value
   at its last movement by more than `StuckBand` (a slow drift counts);
   `Stuck` when it has not moved for `StuckTime`.
2. **[F09.signal.rate]** `Rate` is the change since the previous call per
   second (unchanged when no time passed); `RateHigh` when `MaxRate` > 0
   and |`Rate`| > `MaxRate`.
3. **[F09.signal.enable]** Disabled: both flags FALSE; enabling starts
   afresh from the present value.

## Combines with

`RB_Scale` (the signal), `RB_Alarm` on `Stuck` and `RateHigh`,
`RB_Vote2oo3` (a stuck transmitter as not healthy).

## Not covered

Noise analysis, comparison against a model of the process, signals that
are legitimately constant for long times (disable the check then).
