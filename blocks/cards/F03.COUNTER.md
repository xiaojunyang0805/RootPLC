# F03.COUNTER · `RB_Counter`

**Family:** F03 timing, counting · **Level:** L1 elementary function ·
**Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

Counts pieces, cycles or pulses up to a preset, with batch counting that
can restart by itself and a lifetime total that is never reset.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `In` | in | BOOL | FALSE | counts on the rising edge |
| `Preset` | in | UDINT | 10 | batch size |
| `AutoRestart` | in | BOOL | FALSE | TRUE: the next count starts a new batch |
| `Reset` | in | BOOL | FALSE | rising edge: count back to 0 |
| `Count` | out | UDINT | | count in the batch |
| `Done` | out | BOOL | | `Count` ≥ `Preset` |
| `Remaining` | out | UDINT | | `Preset` − `Count`, at least 0 |
| `BatchDone` | out | BOOL | | TRUE for one call when a batch completes |
| `Batches` | out | UDINT | | completed batches |
| `Total` | out | UDINT | | every counted edge, never reset |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F03.counter.count]** Each rising edge of `In` adds one to `Total`
   and, below the preset, to `Count`.
2. **[F03.counter.batch]** Reaching the preset sets `Done`, gives
   `BatchDone` for that call and adds one to `Batches`.
3. **[F03.counter.restart]** With `AutoRestart`, the next edge after the
   preset starts a new batch at 1; without it `Count` stays at the preset.
4. **[F03.counter.reset]** A rising edge of `Reset` sets `Count` to 0
   (`Total` and `Batches` stay).
