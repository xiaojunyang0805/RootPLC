# F04.MOTOR.DOL · `RB_Motor`

**Family:** F04 device modules · **Level:** L2 device module ·
**Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

Starts and stops a motor direct on line through one contactor, with
running feedback, a thermal overload input, a restart delay, a mode, an
interlock and a permissive.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `Mode` | in | `RB_MODE` | `Off` | `Off`, `Manual` or `Auto` ([blocks.mode]) |
| `AutoRun` / `ManRun` | in | BOOL | FALSE | automatic / manual run command (level) |
| `Interlock` | in | BOOL | FALSE | TRUE stops now, in every mode |
| `Permissive` | in | BOOL | TRUE | FALSE: do not start |
| `FbRunning` | in | BOOL | FALSE | contactor auxiliary contact |
| `Overload` | in | BOOL | FALSE | TRUE: thermal overload tripped |
| `Feedback` | in | BOOL | TRUE | FALSE when no running feedback is wired |
| `FeedbackTime` | in | TIME | T#2s | supervision time |
| `RestartDelay` | in | TIME | T#0s | minimum time off before a start |
| `Reset` | in | BOOL | FALSE | rising edge clears a fault |
| `Run` | out | BOOL | | contactor output |
| `Running` | out | BOOL | | running, from the feedback |
| `Error` / `ErrorID` | out | BOOL / UDINT | | fault ([blocks.fault]) |
| `Status` | out | `RB_DEVICE_STATUS` | | for the HMI ([blocks.status]) |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F04.motor.mode]** In `Auto` the motor follows `AutoRun`, in `Manual`
   `ManRun`, in `Off` it is stopped.
2. **[F04.motor.interlock]** `Interlock` TRUE stops the motor at once, in
   every mode.
3. **[F04.motor.permissive]** `Permissive` FALSE prevents a start, not
   running on.
4. **[F04.motor.restart-delay]** A start needs the contactor to have been
   off for `RestartDelay`, counted from the moment it dropped (also from
   the block's first call).
5. **[F04.motor.overload]** `Overload` TRUE is fault 3 at once.
6. **[F04.motor.no-feedback]** Run commanded, `FbRunning` FALSE for
   `FeedbackTime`: fault 1.
7. **[F04.motor.stuck]** Not commanded, `FbRunning` TRUE for
   `FeedbackTime`: fault 2 (contactor stuck).
8. **[F04.motor.fault]** A fault latches and drops the contactor (safe
   state: de-energised). A rising edge of `Reset` clears it; a cause still
   present is detected again (overload at once).
9. **[F04.motor.no-supervision]** With `Feedback` FALSE, `Running` follows
   the command and there is no feedback supervision; switching it on starts
   the timer fresh.
10. **[F04.motor.status]** `Status.Starts` counts starts; `Status` mirrors
    mode, command, running and fault.

## Faults

| ErrorID | Meaning | Cleared by |
|---|---|---|
| 1 | no running feedback within `FeedbackTime` after a start | `Reset` |
| 2 | running feedback without a command (contactor stuck) | `Reset` |
| 3 | thermal overload | `Reset` after the overload resets |

## Combines with

F09 run-hour meters and maintenance intervals on `Status.Starts` /
`Running`, F08 alarms on `Error`, F12 conveyor zones and pumps, F10 mode
managers driving `Mode`.

## Not covered

Star-delta (`RB_MotorStarDelta`) and soft starters, variable-speed drives
(`RB_Drive`), two-speed motors
(`RB_MotorTwoSpeed`), motor protection relays with
current measurement, safe torque off (a safety function).
