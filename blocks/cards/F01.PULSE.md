# F01.PULSE · `RB_PulseRate`

**Family:** F01 signal conditioning · **Level:** L1 elementary function ·
**Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

A rate and a total from a pulse input: flow meters, energy meters,
counting wheels, speed sensors.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `Pulse` | in | BOOL | FALSE | the pulse input |
| `Factor` | in | LREAL | 1.0 | units per pulse |
| `Window` | in | TIME | T#1s | gate time |
| `TimeBase` | in | TIME | T#1h | rate unit: per hour, per minute, ... |
| `Reset` | in | BOOL | FALSE | rising edge: `Total` to 0 |
| `Rate` | out | LREAL | | units per `TimeBase`, updated each window |
| `Total` | out | LREAL | | units since the last reset |
| `Pulses` | out | UDINT | | pulses in the current window |
| `Error` / `ErrorID` | out | BOOL / UDINT | | settings fault ([blocks.fault]) |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F01.pulse.count]** Each rising edge of `Pulse` adds 1 to `Pulses` and
   `Factor` to `Total`.
2. **[F01.pulse.rate]** At the end of each `Window`: `Rate` = pulses ×
   `Factor` × `TimeBase` / `Window`, then the window starts again (exact
   TIME arithmetic). Without pulses the rate is 0 after one window.
3. **[F01.pulse.limits]** The pulse must stay on and off for at least one
   PLC cycle each; faster signals need a counter module.
4. **[F01.pulse.settings]** `Window` T#0s is fault 1: `Rate` 0, nothing
   counted into the window.

## Faults

| ErrorID | Meaning | Cleared by |
|---|---|---|
| 1 | `Window` is T#0s | a valid `Window` |

## Combines with

rate), `RB_AnalogLimits` (low or high flow), F11 data handling.

## Not covered

retained totals.
