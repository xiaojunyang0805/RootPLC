# F02.BYPASS · `RB_Bypass`

**Family:** F02 discrete logic and interlocks · **Level:** L1 elementary
function · **Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

A maintenance bypass of one interlock or permissive: allowed only with a
key switch, limited in time and counted, so a forced condition cannot be
forgotten. Not for safety functions.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `Cond` | in | BOOL | FALSE | the real condition, TRUE = ok |
| `Request` | in | BOOL | FALSE | rising edge: start the bypass |
| `Permit` | in | BOOL | FALSE | key switch |
| `Cancel` | in | BOOL | FALSE | rising edge: end it |
| `MaxTime` | in | TIME | T#30m | the bypass ends after this |
| `Out` | out | BOOL | | `Cond` OR the bypass |
| `Active` | out | BOOL | | the bypass is on |
| `Remaining` | out | TIME | | time left |
| `Uses` | out | UDINT | | bypasses started |
| `Expired` | out | BOOL | | TRUE for one call when `MaxTime` ran out |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F02.bypass.start]** A rising edge of `Request` with `Permit` starts
   the bypass (not while it is active) and counts it.
2. **[F02.bypass.out]** `Out` is `Cond` OR `Active`.
3. **[F02.bypass.end]** The bypass ends after `MaxTime` (`Expired` for one
   call), on a rising edge of `Cancel`, or when `Permit` goes FALSE.

## Tests

`conformance/cases/blocks/ok_rb_round5.st` (`bypass_*`). Library mutation score against all block tests: 99% (1233 of 1237 library mutants, 5 Nov 2026; the four survivors are equivalent mutants in `RB_MotorReversing`, `RB_AlarmSummary` and `RB_Trips`).

## Combines with

`RB_Permissives` and F04 `Interlock` / `Permissive` inputs (`Out` in place
of the condition), `RB_Alarm` on `Active` (shown while bypassed), HMI
logging of `Uses`.

## Not covered

Bypassing safety functions (never in standard PLC logic), several
conditions per block, user identification (a HMI job).
