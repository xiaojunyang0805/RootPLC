# F05.STEPS · `RB_StepChain`

**Family:** F05 sequencing · **Level:** L1 (the frame of every L3 sequence) ·
**Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

Runs a sequence of steps: it keeps the step number, the time in the step,
a first-call flag for one-shot actions, step timeouts, hold and abort. The
application writes what each step does in a `CASE` on `StepNo` and tells
the chain when the current step is finished. This is how most machine
sequences are written in Structured Text.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `Start` | in | BOOL | FALSE | rising edge: idle → step 1 |
| `Proceed` | in | BOOL | FALSE | the current step is finished |
| `NextStep` | in | INT | 0 | 0: next step; otherwise the step to go to |
| `LastStep` | in | INT | 1 | after this step (with `NextStep` 0) the chain is done |
| `StepTimeout` | in | TIME | T#0s | for the current step; T#0s: none |
| `Hold` | in | BOOL | FALSE | TRUE: stay in the step, timer paused |
| `Abort` | in | BOOL | FALSE | TRUE: back to idle |
| `Reset` | in | BOOL | FALSE | rising edge clears a timeout |
| `StepNo` | out | INT | | 0 idle, 1 … |
| `StepTime` | out | TIME | | time in the step, without holds |
| `FirstCall` | out | BOOL | | TRUE in the call in which the step was entered |
| `Busy` / `Held` | out | BOOL | | not idle / held |
| `Done` / `Aborted` | out | BOOL | | TRUE for one call when the chain ends / is aborted |
| `Error` / `ErrorID` | out | BOOL / UDINT | | timeout fault ([blocks.fault]) |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Usage pattern

```
CASE chain.StepNo OF
1: chain(Start := start, Proceed := full,  LastStep := 2, StepTimeout := T#5s);
2: chain(Start := start, Proceed := empty, LastStep := 2, StepTimeout := T#5s);
ELSE
   chain(Start := start, Proceed := FALSE, LastStep := 2, StepTimeout := T#5s);
END_CASE;
inlet  := chain.StepNo = 1;
outlet := chain.StepNo = 2;
```

## Behaviour rules

1. **[F05.steps.start]** In step 0 a rising edge of `Start` enters step 1.
2. **[F05.steps.proceed]** In a step, `Proceed` TRUE moves to `NextStep`
   (or the next step when 0); after `LastStep` with `NextStep` 0 the chain
   returns to 0 and gives `Done` for one call. A jump to any step (also
   back) keeps the chain running.
3. **[F05.steps.first-call]** `FirstCall` is TRUE in the call in which a
   step is entered, so step actions can do one-shot work.
4. **[F05.steps.timeout]** `StepTime` counts the time in the step (not
   while held); reaching `StepTimeout` (when not T#0s) is fault 1, which
   holds the chain in its step (`Proceed` ignored) until a rising edge of
   `Reset` restarts the step's time.
5. **[F05.steps.hold]** `Hold` TRUE keeps the step and pauses its time.
6. **[F05.steps.abort]** `Abort` TRUE returns to step 0 and clears a fault;
   `Aborted` is TRUE for one call when a running chain was aborted; while
   `Abort` is TRUE the chain does not start.

## Faults

| ErrorID | Meaning | Cleared by |
|---|---|---|
| 1 | step timeout | `Reset` (or `Abort`) |

## Combines with

Every L3 equipment function: filling, dosing, homing, pick and place;
F04 device modules in the steps; `RB_Phase` around it for batch control;
F08 alarms on `Error`.

## Not covered

Parallel branches (use several chains), graphical SFC (planned import),
step-specific timeouts as a table (the application sets `StepTimeout` per
step, as in the pattern).
