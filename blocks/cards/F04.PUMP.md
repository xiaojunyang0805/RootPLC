# F04.PUMP · `RB_Pump`

**Family:** F04 device modules · **Level:** L2 device module (built from
`RB_Motor`) · **Library:** RootBlocks 0.1.0 · **Conventions:**
spec/15-blocks.md

## Job

Runs a pump through `RB_Motor` and protects it against running dry: a
level or flow switch that reports no liquid while the pump runs stops it
after `DryRunTime`. It is the first catalog block built from another one.

## Interface

All inputs and outputs of `RB_Motor` (card F04.MOTOR.DOL), plus:

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `DryRun` | in | BOOL | FALSE | TRUE: no liquid (level or flow switch) |
| `DryRunTime` | in | TIME | T#10s | dry running this long while running: fault 4 |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F04.pump.motor]** Modes, interlock, permissive, restart delay,
   feedback, overload and their faults (1–3) are those of `RB_Motor`.
2. **[F04.pump.dry-run]** `DryRun` TRUE while the pump is running for
   `DryRunTime`: fault 4; the pump stops in the same call.
3. **[F04.pump.stopped]** `DryRun` while the pump is stopped is not a fault
   (an application that must not start without liquid maps it to
   `Permissive` or `Interlock`).
4. **[F04.pump.fault]** Fault 4 latches until a rising edge of `Reset`,
   which also resets the motor. A motor fault takes precedence: its
   `ErrorID` is reported.

## Faults

| ErrorID | Meaning | Cleared by |
|---|---|---|
| 1–3 | as `RB_Motor` | `Reset` |
| 4 | dry running for `DryRunTime` | `Reset` |

## Not covered

measurement (F01 scaling feeds them), cavitation detection.
