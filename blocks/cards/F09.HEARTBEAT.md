# F09.HEARTBEAT · `RB_Heartbeat`

**Family:** F09 supervision and diagnostics · **Level:** L1 elementary
function · **Library:** RootBlocks 0.1.0 · **Conventions:** spec/15-blocks.md

## Job

Shows partners (SCADA, an HMI, another PLC) that this controller is alive
with a toggling signal, and supervises theirs: a partner whose signal
stops changing is reported lost, so the application can go to a safe
state or alarm.

## Interface

| Name | Direction | Type | Default | Meaning |
|---|---|---|---|---|
| `PartnerBeat` | in | BOOL | FALSE | the partner's toggling signal |
| `Period` | in | TIME | T#1s | own signal changes every `Period` |
| `Timeout` | in | TIME | T#5s | no change this long: partner lost |
| `Beat` | out | BOOL | | own toggling signal |
| `Alive` | out | BOOL | | the partner's signal changed within `Timeout` |
| `LostCount` | out | UDINT | | times the partner was lost |

Inputs keep their last value between calls (IEC 61131-3 function-block
inputs), so pass every input that changes, in every call.

## Behaviour rules

1. **[F09.heartbeat.beat]** `Beat` changes every `Period`.
2. **[F09.heartbeat.alive]** `Alive` is FALSE when `PartnerBeat` has not
   changed for `Timeout`, counted from its last change (or the first call);
   any change makes it TRUE again.
3. **[F09.heartbeat.lost]** Each change from alive to lost adds one to
   `LostCount`.
