# X1: IronPLC differential, 4 Nov 2026

IronPLC 0.241.0 (official Linux release, run in WSL, out of process; none of
its code or library sources used) checked every conformance case in its
strict IEC 61131-3 ed.3 mode and its TwinCAT mode
(`python eval/oracle/ironplc_diff.py`). 190 cases compared, 9 use RootPLC's
TEST extensions (n/a).

| Outcome | Cases | Triage |
|---|---|---|
| Agree | 68 | |
| RootPLC rejects, IronPLC accepts | 18 | **Theirs**: IronPLC misses checks (unknown member `tmr.QQ`, duplicate names `speed` / `SPEED`, literal out of range, bad escapes, writes to an FB's internal variable, constant index out of bounds, ...). Spot-checked; candidates for upstream reports. |
| RootPLC accepts, IronPLC accepts with three tolerances | 10 | **Policy**: no `;` after `END_IF` / `END_FOR` (strict IEC requires it), `//` comments (IEC ed.3 allows them, IronPLC's ed.3 mode does not), `{attribute}` pragmas. |
| RootPLC accepts, IronPLC still rejects | 94 | Mostly **theirs (not implemented)**: ed.3 OOP parts (methods and properties in interfaces and blocks, NAMESPACE, CLASS, `SUPER^()`), typed enumerations with a base type, `CHAR#'a'`, `T#1h_30m`, the `TO_*` conversions, extensible `ADD`, `TASK(INTERVAL := ...)`, and vendor forms its TwinCAT mode lacks (`E.V`, empty `Done =>` outputs, `FOR` over array elements, PROPERTY). Three are **policy questions for RootPLC**: lower-case hex digits (`16#ff`), `TOD#12:00` without seconds and a function called as a statement, all accepted without a warning although strict IEC does not allow them. |
