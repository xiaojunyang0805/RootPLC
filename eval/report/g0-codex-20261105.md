## Method

- Each run starts in a fresh directory with the task prompt, an empty `src/` and the visible tests.
- Mode *with*: `rootplc` on PATH, its MCP server configured, AGENTS.md in the directory. Mode *without*: no RootPLC anywhere.
- Grading uses only the agent's `src/` plus the task's test files, run by `rootplc test`; the agent never sees the hidden tests.
- Reference solutions pass all tests; hidden tests kill most mutants of the reference (`eval/harness/validate_bench.py`).

## Findings (written 5 Nov 2026)

1. **RootPLC raises Codex's verified-correct rate by 11 points** (80% → 91%,
   54 runs per mode) and compile rate by 6 points. The gains are on
   migration (`migrate-legacy-heater`: 0/2 → 2/2; `migrate-twincat-dosing`:
   correct behaviour with a vendor form → 2/2 strict IEC), timers
   (`run-hours`: compiles only → 2/2; `level-alarm-delay`: 1/2 → 2/2) and
   strict IEC (IEC clean 67% → 83%).
2. **Codex wrote no tests of its own in either mode**, although AGENTS.md
   asks for a test with every change; so no mutation score could be measured.
   Claude Code wrote tests in 100% of runs with RootPLC (0% without). For
   Codex, RootPLC improves correctness but not yet evidence. Since this run,
   `rootplc test --mutate`, `rootplc evidence` and a stronger
   `write_and_verify` prompt exist; the next Codex run measures whether they
   change this.
3. **Remaining failures.**
   - `recipe-parser`: both modes use string functions that are not IEC
     61131-3 (`ORD`, `UPPER_CASE`). With RootPLC, Codex ran the checker, saw
     these errors and stopped without fixing them.
   - `filling-station` (a long sequence with pause and timeouts): compiles in
     both modes, 2–5 of 12 hidden tests pass. Claude Code solved it 3/3 in
     both modes.
   - `valve-monitor`: 1 of 2 runs with RootPLC misses one hidden test
     (timeout and reset); 2/2 without. With 2 runs per task this is within
     run-to-run variation.
4. **Harness fix found by this run.** The task prompt of
   `migrate-legacy-heater` mentions `rootplc check`, and the pick detector
   matched the agent quoting the prompt, so 2 runs *without* RootPLC were
   counted as using it. Use is now counted only in mode *with* (where
   rootplc is on PATH); this report and its results are corrected.
